## Result and common mechanism

Most route entry queries and selected panels already fetch saved projections automatically. The main systemic defect is that **automatic reading is being treated as automatic data availability**. Routine history/company preparation is explicitly click-only, some ordinary financial data requests require confirmation, frozen readers opt out of publication updates, failures depend on another event/remount/manual retry, and many panels release their display cache immediately. Making the existing buttons small does not fix these behaviors.

The correct closure is demand-driven, bounded service orchestration for an admitted selection: reuse saved display data immediately; determine which required inputs are missing/stale; acquire or prepare only those inputs using configured/entitled providers; deduplicate work; follow its durable progress; publish useful typed results into the active screen. Explicit source configuration, credentials/OAuth, file import/reconciliation, saved preferences/results, virtual orders/session changes, backup/restore/retention, update activation and repair/removal remain deliberate. Do not indiscriminately call every mutation from a React effect.
