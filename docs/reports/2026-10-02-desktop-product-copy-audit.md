## Retain / rejected false positives

- `investment-financials.tsx` ratio `×` is aria-hidden and “times” is screen-reader-only. Extracted DOM text `1.23× times` is not evidence of visible duplication. The analogous shared PercentageChange duplication is intentional accessible output.
- `preparation-controls.tsx` sets `preparation.error` to its own fixed UI strings. It is poor wording in places, not a proved arbitrary-error leak. Likewise WorkspaceRecovery's `product.error` comes from fixed strings in `app/product-context.tsx:395,416`.
- `messageFrom` is also used in Settings and logs for operational recovery. A global replacement could erase useful recovery instructions; trace each ordinary caller instead.
- Portfolio price methods are closed product values (`Last trade`, `Bid-ask midpoint`) in `portfolio-contracts.ts:582`; cost-basis methods at `:79` are ordinary financial names. Neither is a proved raw-enum leak.
- Do not remove valid financial distinctions: preliminary/revised information, model uncertainty/calibration gaps, no matching pattern, abstentions, missing financial families, unsupported source areas, original versus later information, simulated trading, bid/ask/last trade, split-adjusted prices, expiry intervals, exact money and probability scale.
- Training/validation/test splits, model names, confidence intervals and point-in-time financial evidence are meaningful advanced concepts. Improve their explanations without substituting false confidence or unsupported availability.
- `components/charts/market-price-chart.tsx:223` can display an observation quality value, but this audit did not establish a concrete ugly runtime producer value. `lib/quality.ts` static technical labels also need caller confirmation before a claim that a current screen shows them. These are mapping-review candidates, not proven additional defects.
- `components/domain-page.tsx` was inventoried but has no current route caller. Do not treat a retained unused renderer as a visited live screen.
