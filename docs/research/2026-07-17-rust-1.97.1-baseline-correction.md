# Rust 1.97.1 Baseline Correction

Date: 2026-07-17
Decision status: binding production-baseline correction

## Decision

Market Squawk pins Rust 1.97.1 and declares a workspace `rust-version` of 1.97.1. Rust 1.97.0 is
ineligible for release builds, benchmarks, checkpoint evidence, or approvals.

This is a corrective point-release update within the specified Rust 1.97 stable line. Edition 2024
and Cargo resolver 3 remain unchanged. Dated research that accurately records earlier 1.97.0 work
remains historical evidence; current architecture, CI, verification, and active implementation
plans must use 1.97.1.

## Primary-source evidence

- The Rust Release Team published [Rust 1.97.1 on 2026-07-16](https://blog.rust-lang.org/2026/07/16/Rust-1.97.1/)
  and states that the point release fixes an LLVM optimization miscompilation. The release includes
  both an LLVM fix and a backport that disables the Rust 1.97.0 IR change that made the problem more
  likely.
- Upstream compiler issue [rust-lang/rust #159035](https://github.com/rust-lang/rust/issues/159035)
  is labeled `P-critical`, `I-miscompile`, `O-x86_64`, and `regression-from-stable-to-stable`. Its
  minimal optimized reproduction succeeds under Rust 1.96.1 but segfaults under Rust 1.97.0.

## Required verification consequences

1. `rust-toolchain.toml`, the workspace MSRV, and all CI jobs name 1.97.1 exactly.
2. CI pin tests reject any reintroduction of a 1.97.0 job.
3. Existing Q2 benchmark/build evidence produced under 1.97.0 is non-authoritative and must be
   regenerated at an exact clean 1.97.1 head.
4. Toolchain fingerprints must bind the actual 1.97.1 `cargo`, `rustc`, standard library/sysroot,
   linker, and relevant SDK closure rather than trusting a `rustup` proxy name.
5. Private implementation facts used by retained-memory formulas must be revalidated against the
   exact 1.97.1 source/toolchain before Q2 memory-accounting approval.
